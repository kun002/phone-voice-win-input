# 手机语音输入到 Windows 输入框

> Phone voice typing for any Windows input box over the local network.

这是一个轻量局域网工具：Windows 端运行 Python 服务，手机浏览器打开采集页，用手机输入法的麦克风语音输入；手机不显示识别文字，只把文字作为传输流自动同步到 Windows 锁定目标输入框。

![轻量桌面 GUI](docs/gui-overview.png)

现在支持：

- 启动后显示手机扫码二维码。
- 启动时生成 `last-phone-qr.png` 和 `last-phone-qr-1.png` / `last-phone-qr-2.png` 等候选二维码，手机优先扫同网段的 PNG 或电脑状态页二维码。
- 手机端 WebSocket 自动连接、断线重连、连接状态显示。
- HTTP 发送 fallback，WebSocket 不可用时仍能用。
- 手机端是纯采集面板：没有可见文本框，不显示识别文字，也没有发送按钮。
- 手机端会自动把识别文字同步到 Windows 锁定目标输入框；电脑状态页 / GUI 同时保留“发送预览”和“清空预览”作为兜底。
- 手机端开始输入时会自动锁定 Windows 当时的前台输入目标，并尽量记录输入光标位置，后续切换窗口或同窗口切换输入框时会尽量回到锁定目标再粘贴。
- 电脑端发送预览、清空预览、释放目标，或手机端一段输入空闲收尾后，会清空手机端隐藏缓存并释放目标；下一段语音会重新锁定当前 Windows 输入框。
- 手机页面刷新、关闭或被浏览器回收时会尽量主动释放目标锁；目标锁也会在默认 60 秒无手机文本活动后自动释放，避免旧手机页面或断线页面长期占用激活设备。
- 手机端不保存历史或可见正文，电脑端预览/目标应用负责承载内容。
- 手机端只使用系统/输入法自带语音，不再调用浏览器 Web Speech API。
- 默认 token 会保存到 `.phone_voice_token`，电脑端重启后手机重连不容易 403。
- 状态页和 GUI 可运行中重生成 token，旧手机链接会立即失效并释放当前目标锁。
- 电脑端运行设置会保存到 `.phone_voice_settings.json`，重启服务后继续使用上次设置；不保存手机输入正文、预览或错误日志。
- 默认保护 Windows 文本剪贴板，粘贴后尽量恢复原文本剪贴板。
- 手机端不需要安装 App；PWA 基础外壳只是可选快捷入口，可尝试添加到主屏幕，主屏幕入口会保留已配对 token。PWA 可以理解成“网页像 App 一样放到主屏幕”，不是另外安装一个原生 App。
- 可选现代桌面 GUI：基于 PySide6，提供概览、手机连接、输入设置、设备与日志以及系统托盘。
- 电脑状态页和 GUI 会显示网络诊断提示，手机连不上时优先排查同网段和 Windows 防火墙。
- 可选 Windows 全局热键：快速暂停/恢复接收，默认关闭，避免和已有快捷键冲突。

## 为什么自己做

我查到的成熟项目都能覆盖一部分场景，但没有完全贴合“手机语音输入后直接灌到 Windows 当前输入框”的小工具：

- [KDE Connect](https://kdeconnect.kde.org/)：成熟、开源、跨平台，支持手机和电脑通信，也支持虚拟触控板/键盘。适合先试，不想写代码时优先考虑。
- [LocalSend](https://github.com/localsend/localsend)：成熟、开源、跨平台，适合在局域网发文本和文件，但不会自动粘贴到当前输入框。
- [scrcpy](https://github.com/Genymobile/scrcpy)：成熟、开源，重点是从电脑控制 Android，方向和这个需求相反。

所以这里做了一个专用版：不装手机 App；核心服务不依赖第三方 Python 包，现代桌面 GUI 仅增加官方 PySide6 依赖。

## 运行

要求：Windows 10/11、Python 3.10 或更高版本，以及处于同一局域网的手机。

在 Windows PowerShell 里：

```powershell
cd .\phone-voice-win-input
.\start.ps1
```

或直接：

```powershell
python .\phone_voice_win_input.py
```

启动后终端会打印一个类似这样的地址：

```text
http://192.168.1.23:8765/?token=随机字符串
```

手机和 Windows 电脑连接同一个 Wi-Fi，用手机浏览器打开这个地址。

终端也会显示字符二维码，但终端字体/缩放可能导致手机识别失败。更稳的方式是打开启动时生成的 PNG 文件。如果有多个文件，优先扫和手机同网段的地址，例如手机是 `192.168.110.x`，就扫 URL 里也是 `192.168.110.x` 的二维码。

```text
.\last-phone-qr.png
.\last-phone-qr-1.png
.\last-phone-qr-2.png
```

也可以打开电脑端状态页扫码，状态页类似：

```text
http://127.0.0.1:8765/desktop?token=随机字符串
```

## 使用

1. 在 Windows 上点击目标输入框，让光标停在那里。
2. 手机上打开网页，点中间的采集区域，让系统键盘出来。
3. 用手机输入法自带的麦克风语音输入。
4. 识别文字会自动同步到 Windows 锁定输入框，同时也会出现在电脑端状态页 / GUI 的预览区；手机上不显示正文。
5. 说完后，直接在目标应用里发送。电脑端“发送预览”只作为重新写入目标输入框的兜底；如果这段不要了，点“清空预览”。

自动同步默认只发送手机端新增的后缀，不再每次用手机全文替换电脑输入框。因此你在 Windows 输入框里手动改过的文字，会尽量保留下来；如果微信输入法这类键盘回头修正了当前活动段最近一小段文字，工具会用“删除旧尾巴 + 写入新尾巴”的方式同步纠错。输入暂停一小会儿后，前面已经同步的内容会进入保护区；后续尾部删除最多只能删未保护区，不能跨过保护边界。如果手机输入法再回头动到保护区，工具不会改电脑前文，而是把当前位置当成新段起点，后面继续说就从新段开始同步。确实想用手机端完整预览重写目标输入框时，再点电脑端“发送预览”。

手机端默认开启 15 秒自动收尾：最后一次非空识别文本后空闲 15 秒，会清空手机隐藏缓存并释放目标。手机输入法短暂清空文本会被当成输入法中间态，只推进保护边界；如果你希望长停顿也不断段，可以在电脑状态页 / GUI 改成“关闭（不自动收尾）”。如果你手动点电脑端“释放目标”，也会同步清掉手机隐藏缓存，避免下一句带着上一句尾巴。
自动收尾时间、目标锁超时和尾部纠错范围可以在电脑状态页 / GUI 的运行设置里调整；目标锁超时和自动收尾的单位是秒，范围 0-60；尾部纠错的单位是字，固定选项为 0/20/50/100/200/500 字。三者都可以选 0 表示关闭。

远程桌面、远程 Agent、云电脑这类输入框，本机 Windows 通常看不到里面真实的文本光标。新版会在拿不到 caret/focus 时，把“开始手机输入那一刻鼠标所在的远程窗口位置”作为弱锁定点；所以远程场景推荐先在远程输入框里用鼠标点一下，然后再从手机开始说。为了避免远程光标乱跳，鼠标位置锁定不再强制回点；只有开启“目标位置回点”且需要切回目标窗口时，才会尝试回点。远程桌面里如果光标还乱跳，优先在电脑状态页 / GUI 关闭“目标位置回点”。
开始输入后，手机页面会显示“目标已锁定”。锁定期间，即使你在 Windows 上临时切换去看其他 Agent 或 demo，同步时也会先尝试切回最初锁定的窗口/控件再写入。如果 Windows 能提供输入光标位置，手机端会显示“已记录输入位置”，后续写入前会短暂回点原位置，减少同一个窗口里误发到另一个输入框的概率。电脑端“发送预览”或“清空预览”、手机页面刷新、关闭、被浏览器回收或手机端自动收尾时，会尽量释放目标锁；如果手机文本长时间没有变化，目标锁也会按设置自动释放，默认是 60 秒，可在状态页/GUI 调整或关闭。手机页面刷新或 WebSocket 重连时，会从电脑端恢复当前目标锁状态，避免误以为未锁定。
可以同时打开多台手机或多个手机页面，但同一时间只有一台会成为“激活输入设备”。激活设备可以锁定目标并写入 Windows；其他设备仍可连接和预览，但写入会被拒绝，直到当前激活设备释放目标或释放全部目标。状态页和 GUI 会显示当前激活设备。

手机端不提供任何设置、历史记录、快捷标点、正文预览或发送按钮，也不显示普通同步过程提示。手机隐藏输入框也会尽量把输入光标保持在末尾，减少输入法浮标乱跳导致新字插进旧草稿前面的情况。暂停/恢复接收、释放目标、重生成 token、测试粘贴、发送预览、清空预览等都在电脑状态页或 GUI 上操作。手机端只负责唤起系统输入法麦克风，并把识别结果同步到电脑输入框。

当前手机端不再提供“网页语音/连续网页语音”按钮。语音来源就是 iOS/Android 系统键盘或输入法里的麦克风；后续如果要接第三方语音服务，会单独做成可选能力。

如果刚升级后手机端仍像旧版一样只同步一次，请刷新手机页面，或关闭后重新扫码打开。PWA/浏览器可能短时间保留旧脚本。
如果已经把手机端添加到主屏幕，后续从主屏幕打开时会继续携带当前 token；如果电脑 IP、端口或 token 变了，仍然需要重新扫码或重新打开新的链接。
手机端隐藏输入缓存只存在于当前页面；刷新、返回再打开或 PWA 被系统回收后，会作为新一段重新开始。

如果目标程序是管理员权限运行的，普通权限的 Python 可能无法发送 Ctrl+V。此时用管理员权限启动 PowerShell 再运行本工具。

目标锁定依赖 Windows 前台窗口和焦点控件。默认写入方式是 `Unicode 直打（远程）`：工具会通过 Win32 API 激活锁定窗口后直接发送 Unicode 键盘事件，不依赖 `Ctrl+V`。当锁定窗口已经在前台时，增量写入和尾部纠错会保留当前光标，因此可以在电脑端把光标插到某个字后面，再从该位置继续语音输入；当程序需要从其他窗口切回目标时，才会把光标移动到末尾作为安全兜底。远程兜底使用带扩展键标记的 `Ctrl+End`，避免被远程桌面误识别成数字小键盘 `1`。如果切到 `剪贴板 Ctrl+V`，粘贴瞬间可能会看到窗口短暂切回目标程序。如果锁定窗口已关闭、权限不足或 Windows 阻止切回，工具会报错并拒绝写入，避免误发到当前焦点。
仍会优先尝试“原生控件后台写入”：当锁定目标是 Windows 原生 `Edit` / `RichEdit` / WinForms Edit 文本控件时，程序会直接把文本写入该控件，不切换前台窗口，也不占用剪贴板。浏览器、Electron、VS Code、网页输入框等目标通常不支持这种方式，会自动回退到目标恢复 + 目标位置回点 + 当前写入方式。

如果远程 Agent 或远程输入框持续打出 `v` / `VVVV`，说明当前实际写入仍然走到了 `Ctrl+V` 路径，或者旧电脑端进程还没重启。新版默认是 `Unicode 直打（远程）`；电脑状态页 / GUI 顶部会显示当前写入方式和最近实际方法，正常应看到 `Unicode 直打` / `unicode_keyboard`。
推荐保持“写入时置前目标窗口”开启：这样浏览器/Electron/Agent 输入框更容易成功写入。之前尝试过“粘贴后自动回到原窗口”，但部分目标应用会因此来不及接收粘贴，所以现在它是独立实验项，默认关闭。如果完全不想切回，可以在 GUI/状态页关闭“写入时置前目标窗口”，或启动时加 `--no-foreground-restore` / `-NoForegroundRestore`。关闭后，能后台写入的原生控件仍会静默写入；普通粘贴会尝试向锁定窗口发送后台粘贴消息，不能安全后台写入时会拒绝发送并提示原因，避免再打出 `a/v` 这类错误字符。如果某个软件只是不适合自动回点，尤其是远程桌面里光标会乱跳，但可以接受切回窗口，可以只关闭“目标位置回点”，或启动时加 `--no-target-click-restore`。

## 现代桌面 GUI

GUI 使用官方 PySide6。首次在新环境运行时安装依赖：

```powershell
python -m pip install -r .\requirements-gui.txt
```

然后启动：

```powershell
.\start.ps1 -Gui
```

现代 GUI 是紧凑小工具窗口，左侧只保留“主页 / 设置 / 日志”三项。主页合并二维码、手机状态、目标状态、写入方式和常用操作；设置页用一个面板管理全部输入行为；日志页集中显示手机、目标、网络诊断和最近错误。

Windows 下使用 Qt 系统托盘，关闭窗口后默认隐藏到托盘继续运行；托盘菜单可显示窗口、暂停/恢复接收、复制手机链接、打开状态页和退出服务。如果 PySide6 未安装，程序会给出提示并回退到旧 Tkinter 界面。
GUI 和电脑端状态页都提供“暂停接收 / 恢复接收”“释放全部目标”“测试粘贴”和“重生成 token”，用于从电脑端快速刹车、解除目标锁、确认锁定目标能正常接收输入，或让旧手机链接立即失效。电脑端状态页还可以按单台设备释放目标，适合多设备或多 Agent 切换时只解开其中一个锁；释放当前激活设备后，下一台设备才能开始写入。
重生成 token 会写回 `.phone_voice_token`，释放当前锁定目标，并刷新 GUI/状态页上的二维码；旧手机页面会开始 403，需要重新扫码。
GUI 和电脑端状态页都可以修改运行设置：是否保护文本剪贴板、写入方式、是否优先尝试原生控件后台写入、是否写入时置前目标窗口、是否启用目标位置回点、是否实验性地粘贴后回到原窗口、目标锁超时、自动收尾时间、尾部纠错范围。写入方式、剪贴板保护、原生控件后台写入、写入时置前目标窗口、目标位置回点、粘贴后回到原窗口、目标锁超时、自动收尾时间和尾部纠错范围会立即影响后续同步，并保存到 `.phone_voice_settings.json`，重启后自动恢复。这个文件只保存设置；如果想完全恢复默认值，停止服务后删除它即可。

如果想在电脑端随时一键暂停/恢复接收，可以启动时加全局热键，例如：

```powershell
.\start.ps1 -Gui -Hotkey ctrl+alt+p
```

热键默认不启用，避免抢占你已有的系统或软件快捷键。支持 `ctrl`、`alt`、`shift`、`win` 加字母/数字、`F1`-`F24`、`space`、`esc`、`pause`，例如 `ctrl+shift+f12`。

`测试粘贴` 只会对已经锁定目标的设备生效。它会粘贴短测试文本，然后立刻尝试 `Ctrl+Z` 撤销，尽量不留下测试内容；如果没有锁定目标，会直接报错，不会把测试文本打到当前窗口。

状态页和 GUI 会显示每台手机的预览片段。预览只保留在当前运行进程内，并截断显示，方便在电脑端确认后发送。
状态页和 GUI 还会显示最近错误摘要，例如 token 失败、目标锁定失败、目标恢复失败、测试粘贴失败等。错误日志只保存在当前进程内，只记录设备、动作、字符数和简短原因，不记录手机输入的完整文本。
状态页和 GUI 还会显示网络诊断提示。如果没有检测到局域网地址、服务只绑定到 `127.0.0.1`，或还没有任何手机连上，会提示检查同一网段、绑定地址和 Windows 防火墙。诊断只基于电脑端能看到的信息，不会扫描局域网。

## 参数

```powershell
python .\phone_voice_win_input.py --port 8899
python .\phone_voice_win_input.py --token my-secret
python .\phone_voice_win_input.py --reset-token
python .\phone_voice_win_input.py --no-token
python .\phone_voice_win_input.py --strict-port
python .\phone_voice_win_input.py --no-clipboard-protect
python .\phone_voice_win_input.py --no-target-click-restore
python .\phone_voice_win_input.py --no-foreground-restore
python .\phone_voice_win_input.py --return-previous-foreground
python .\phone_voice_win_input.py --target-lock-timeout 60
python .\phone_voice_win_input.py --no-qr
python .\phone_voice_win_input.py --gui
python .\phone_voice_win_input.py --hotkey ctrl+alt+p
python .\phone_voice_win_input.py --dry-run
python .\phone_voice_win_input.py --self-test
```

- `--port`：修改起始端口，默认 `8765`。如果端口不可用，会自动尝试后面的端口。
- `--token`：指定访问 token；默认使用本地持久 token。
- `--reset-token`：重新生成本地持久 token。换 token 后手机需要重新扫码。
- `--no-token`：关闭 token 校验，只建议在可信局域网临时使用。
- `--strict-port`：只使用指定端口，失败时不自动换端口。
- `--no-clipboard-protect`：临时关闭粘贴后的文本剪贴板恢复；启动参数只覆盖本次运行，不会写入 `.phone_voice_settings.json`。
- `--no-target-click-restore`：临时关闭目标位置回点；适合少数不希望工具临时移动鼠标并点击原输入位置的软件。
- `--no-foreground-restore`：临时关闭写入时置前目标窗口；普通粘贴会尝试后台粘贴消息，不能安全后台替换全文时会提示，避免把目标应用拉到最前。
- `--return-previous-foreground`：临时开启实验项，fallback 粘贴后尝试回到原窗口；部分 Electron/浏览器目标可能因此粘贴不稳定，默认关闭。
- `--target-lock-timeout`：临时设置目标锁无手机文本活动后的自动释放秒数，范围 `0-60`；未传时使用保存设置，`0` 表示关闭。
- `--no-qr`：启动时不在终端打印二维码。
- `--gui`：打开轻量桌面窗口，并在 Windows 下尝试启用系统托盘图标。
- `--hotkey`：启用可选 Windows 全局热键，用于暂停/恢复接收，例如 `ctrl+alt+p`。
- `--dry-run`：只测试网页和接口，不碰剪贴板，也不发送按键。
- `--self-test`：运行本地自检。

## 剪贴板保护

当写入方式使用 `剪贴板 Ctrl+V` 时，默认开启文本剪贴板保护：

1. 粘贴前读取 Windows 当前文本剪贴板。
2. 临时把手机文本写入剪贴板并发送 `Ctrl+V`。
3. 粘贴后检查剪贴板是否仍然等于手机文本。
4. 如果仍然相同，恢复原文本剪贴板。
5. 如果已经变成别的内容，说明你在 Windows 上复制了新内容，程序不会覆盖它。

注意：当前保护的是文本剪贴板。图片、文件等非文本剪贴板格式暂不完整恢复。

## 端口被 Windows 拒绝

如果看到：

```text
[WinError 10013] 以一种访问权限不允许的方式做了一个访问套接字的尝试。
```

通常是当前端口被 Windows、Hyper-V、WSL、代理软件或安全软件临时占用/保留。新版脚本会自动尝试后面的端口。也可以手动指定一个端口：

```powershell
.\start.ps1 -Port 8876
```

## 安全注意

- 默认会生成随机 token，手机 URL 里带 token，避免同一局域网里别人随便提交文本。
- 服务绑定到 `0.0.0.0`，方便手机访问；如果只想本机测试，可以用 `--host 127.0.0.1`。
- 默认 `Unicode 直打（远程）` 不使用剪贴板；如果切到 `剪贴板 Ctrl+V`，文本会先写入 Windows 剪贴板，再发送 Ctrl+V，并默认尽量恢复原文本剪贴板。
- 第一次运行时 Windows 防火墙可能会弹窗，需要允许 Python 在专用网络通信。
